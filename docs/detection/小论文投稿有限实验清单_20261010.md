## 3. P0：AP预检的固定任务

### 3.1 范围

1. 先读取B与最终σ1.5 midpoint的选中权重身份、完整VAL逐帧预测及GT。优先复用已有保存框，不加载其他epoch或重训。
2. 按真实375帧、仿真512帧分别报告旋转框AP50、AP75；此处数字为数据数量，不是已有AP成绩。
3. 无输出帧必须保留为空预测，不能仅评价输出帧。不得按中心命中、RIoU或GT误差筛掉帧。
4. 若保存预测缺失、少了score、坐标身份不明或格式不完整，先报告精确缺口；确需固定权重的VAL推理时另行确认执行安排。本地不连接服务器。
5. 原自定义指标及其分母保持：中心命中只统计输出帧，另报输出覆盖和全帧中心正确覆盖。AP不替换这些指标，也不引入中心惩罚版角度误差。

### 3.2 先确定评价口径，后计算

- 复用本项目旋转框IoU与AP实现，明确`le90`、角度单位、原图坐标、GT解析、困难标记处理和匹配规则。
- AP50与AP75分别使用IoU阈值0.50和0.75。必须记录AP积分方式（VOC2007十一点或全点积分）及软件版本；不得把两项称为COCO AP@[0.50:0.95]。
- 本项目`mmrotate/datasets/dota.py`支持单个浮点`iou_thr`；两阈值需分别调用或由专用评价入口组织，不直接向该接口传列表。
- 本项目`CraneDataset.evaluate`会捕获标准mAP异常并跳过。正式预检必须将缺项、异常、非有限值视为未通过，不把日志中存在`mAP`字段视作正确计算的证明。
- **候选集合须明确：** 当前B与midpoint封存的是单帧最终Top-1输出，score继承B。对它们计算的AP须明确标为“固定单目标输出协议下的OBB AP”；该成绩不等同于修改检测头后导出的全候选AP。
- 外部方法后续采用原生检测候选做标准AP、还是统一单目标输出做任务AP，须在P1训练/评价前固定。不能将EOOD多候选结果与其他方法Top-1结果混为相同输出协议，也不能为AP扩大B输出或改变封存方法身份。
- 主表指标与格式先固定，不因AP接近饱和而改IoU阈值、删帧、调score阈值或重选权重。

### 3.3 通过条件与交付

- VAL图像身份、375/512分组及空预测完整；预测和GT均恢复到原图，score和输出数量与封存结果一致。
- 验证完全匹配、IoU不达标、漏检、重复检测和不同score顺序等必要案例；检查AP范围、NaN及异常处理，防止字段存在但计算失败。
- B与midpoint对比使用同一图像、GT、AP实现及分组；原封存score、权重和自定义指标不改变。
- 交付来源清单/哈希、评价口径、按域AP50/AP75、必要验证结果和限制说明。没有真实结果时不在论文填AP占位数字。
- 本清单初稿只整理P0要求；A057获用户授权后新增评价脚本及完整VAL CPU实算，A058核验服务器原生AP回传，结果与本地完全一致，见[AP评价口径与结果](AP评价口径与运行说明_20261010.md)。没有新增训练／外部对照执行授权，不因P0完成自动启动P1。
